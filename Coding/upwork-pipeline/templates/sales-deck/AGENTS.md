# Sales deck authoring rules

Daily content workers edit only their assigned spec and private evidence in the assigned job folder. Never change shared runtime, catalog, compiler, palette, font or template-lock files during a job. Unsupported native tools/actions require a new adapter through explicit template maintenance; do not improvise a fallback.

Astra main explicitly selects `gpt-6.1-sol` high workers with `fork_turns: none`, short original requirements and isolated folders. Main adapts the queue to exposed session capacity and sends each build to independent Astra xhigh review with bounded screenshots and behavior checks. Main records the verdict against the exact page hash with the pipeline `recording-queue review` command. All daily sessions use its canonical default `.local/recording-queue`; no per-chat store or routine `--root` override. Built pages await review; builders cannot approve their own work.

Routine local generation is authorized within the job folder. This is an instruction/integrity boundary, not a sandbox security boundary. Template maintenance is separate. Never change global agent/model settings. Never send, submit or externally publish from this lane. Preserve locked proposal/finalization rules.

Read `BATCH_RUNBOOK.md` for pasted/saved-job intake and fresh-chat kickoff. Workers never run queue commands. Main uses the queue CLI's OS lock; never hand-edit its registry/index or run the isolated `build.py batch` utility into the shared queue. Current capacity is four total agents including main; six is a future configuration only after verification. Start/restart with the pipeline `recording-queue start --port 8769`; it opens no browser. Mark recorded only after Lorenzo's actual Loom. `.local/` state stays private and ignored; this is same-Mac persistence, not cloud sync.
