## Spoken-copy gate (20 October user correction)

The presenter must be able to read the page aloud and immediately explain the result. Check cover headings, chapter headings/captions, custom diagram labels, metric names, CTA and every beat as spoken language. Read a split heading as one continuous line. Avoid compressed developer shorthand such as “Agree the product. Test one journey.”, “permission boundary”, “manual touches” or “duplicate safety” in sales narration. State the actual action: “Let's map out your first feature”, “which records each user can access”, “steps your team handles” or “prevent duplicate payment records”. Keep genuine native software labels unchanged; explain them plainly in captions/talking points. Beats are short, usable spoken lines, with click instructions in details when needed. A technically correct interface or schema pass does not pass this copy gate. Main checks the complete read-aloud sequence before independent review; the reviewer checks clarity as well as factual correctness. Do not make Lorenzo translate internal planning language while recording.
