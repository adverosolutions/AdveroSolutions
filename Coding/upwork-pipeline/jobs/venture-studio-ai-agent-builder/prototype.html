Recruiting agent / How it's built

Four pieces, each one you can open and read.

Nothing here is hidden in code. Each piece lives in a tool you can log into, and the order below is the order data moves.

  1. Rubric sheet. One tab per role: the questions, the competencies, and what a 1 and a 5 sound like.
  2. Vapi assistant. Reads the questions from the sheet, holds the call, applies the follow-up rule.
  3. n8n workflow. Four steps: catch the end-of-call webhook, fetch the rubric, ask Claude, write the row.
  4. Claude scoring prompt. Returns JSON: a score, a quote and a reason per competency, then flags and a recommendation.

Every choice, and what we said no to.

Chose
One follow-up rule in the prompt
Instead of

Chose

Instead of

Chose

Chose
Quotes as evidence for every score
Instead of
A bare number the hiring manager has to trust blindly
Recruiting agent / Change it yourself

Add a competency by adding a row.

Open the rubric tab for the role and add a line. The next interview asks about it and the scorecard grows a row for it. No code, no redeploy.

CompetencySounds like a 1Sounds like a 5
Performance ownership"We grew fast"Names spend, CPA and the change that moved it
Creative testing"We tried a lot of ads"Specific hooks, how they were tested, what won
Learning from failureNo failure namedA real mistake and the rule it changed
Stakeholder communication"I kept everyone updated"How a bad week was explained to a founder

To make the interviewer stricter or softer, edit one line of its instructions:

# Vapi assistant, follow-up rule After each answer, check for one concrete example and one number. If either is missing, ask one follow-up that names what's missing.Never ask more than one follow-up per question. Move on politely.

What usually gets built
7 parts
  • Planner agent decides the questions
  • Interviewer agent asks them
  • Follow-up agent decides what's vague
  • Evaluator agent scores
  • Memory store remembers the call
  • Vector database holds the rubric

What ships the same afternoon
4 parts
  • One voice agent with the questions and a follow-up rule Vapi
  • One end-of-call hand-off n8n
  • One scoring call with a rubric Claude
  • One sheet the team already reads Sheets

Add a second agent when the first one's output is trusted and the bottleneck is obvious. Until then, every extra part is one more thing to debug and one less thing your team can change on its own.
