# Outcome sync (proposals.csv viewed / replied / interviewed / hired)
1. Read-only MCP calls, org_uid `2081884703335585732`: `list_freelancer_proposals action=list` once per status `Accepted, Activated, Offered, Hired, Declined, Archived, Withdrawn`. `status`, `limit` and `cursor` all go inside `params`, e.g. `params {"status": "Declined", "limit": 10}`, never top level (the default status is Accepted). Page with `params.cursor` until a page returns no edges (`hasNextPage` stays true even at the end). Save all responses as one JSON list to `<scratchpad>/proposals.json`.
2. Replies: call `list_freelancer_proposals action=get_room params {"proposal_id": ...}` for every still-`Accepted` proposal AND every `Declined` / `Archived` / `Withdrawn` proposal that matches a log row. Save `{"<proposal_id>": <response>}` to `<scratchpad>/rooms.json`. A NOT_FOUND error means the client never messaged; only that writes replied/interviewed "no" on a closed proposal. No get_room call = those stay blank.
3. Hires: `list_contracts action=search` → `<scratchpad>/contracts.json`. Contracts have no job id: one applies only if exactly one proposal has its title, it starts on/after that proposal and the proposal is not Declined/Withdrawn/Archived. The rest print as unmatched contracts.
4. Preview: `python3 sync_outcomes.py --proposals <scratchpad>/proposals.json --rooms <scratchpad>/rooms.json --contracts <scratchpad>/contracts.json --dry-run`. Nothing in proposals.csv changes; the result goes to a temp copy and you get a diff. A "WARNING: skipped malformed row/record" (wrong or ambiguous field count, a quote left open past its line, or unparseable) is left untouched and out of the rates: fix it by hand; its proposal is listed under "belong to a skipped row". "AMBIGUOUS" means several URL-less rows share a proposal title, so none is updated: add the job_url to the right row. "UNMATCHED: row N" means a URL-less row's exact title is a job another row already claims: add its job_url.
5. Apply: same command without `--dry-run`. Values only move up (empty→yes/no, no→yes); only changed rows are rewritten, the result is verified before it replaces the file, the run aborts if anything else wrote proposals.csv meanwhile, and the previous file is kept as `proposals.csv.bak`.
6. Rates: `python3 sync_outcomes.py --report` prints view, reply, interview and hire rates (yes / rows, with counts) by `platform` and `opener_variant`. Skipped malformed rows are never counted; a "not counted" line names them. With `--dry-run` it is labelled "(dry run, not written)".
7. Limits: Upwork does not show "viewed" per proposal. The script only infers it from a reply, interview, hire or a client decline. `Activated` (label "Invitation accepted") = client opened an interview = replied + interviewed. hired "no" = proposal Declined/Archived/Withdrawn.
8. Never call send_message, manage_proposals writes or respond_to_offer for this. The sync is read-only on Upwork.
9. Prefix risk: a row with no job_url is matched by title, and a truncated title by a unique 15+ character prefix; if its own proposal was not fetched, that prefix can match a different job. Always log the job_url.
