**Core philosophy (the whole point):** personalization here = *proof we did 30 seconds of research*, NOT strategic insight. The line is one specific observation, no pitch/greeting/link.

Key design:
- **Auto-selection**: picks the highest-priority angle whose `triggers` match the row's available fields; tags each row with `personalization_type` so angle types can be A/B-split-tested after the fact.
- **Angle library lives in the JSON config, not code** — tune angles/thresholds/voice/banned-words without touching Python. Adding an angle = adding a JSON object (generic trigger evaluator: ops non_empty/equals/in/gte/etc., all/any groups).
- **Voice (locked):** clean sentence case; first-person noticing ("Saw"/"Noticed" — "I noticed"/"I came across" are BANNED); numbers only when flattering (review_count ≥150, rounded down e.g. "500+"); star rating never cited (only an internal ≥4.0 gate for reputation angles).
- **Skip/flag:** rows missing core fields → `SKIPPED_NO_DATA`; API failure → `ERROR_API`; batch never crashes on one row. Out-of-scope (chain/corporate) detection intentionally NOT built — ignored per Lorenzo's call.
- `--dry-run` selects types + builds prompts with zero API spend; `--limit N` for cheap samples.

**Real bugs found via live testing on the 4 real Fort Worth leads (not just unit tests) — this is the same "diff against real output" discipline that caught bugs on 2026-07-01, reapplied here:**
- **Perplexity citation-marker leakage**: `sonar` embeds inline numbered citation refs (`[4]`, `[1][2]`) directly IN the fact text it returns, not just in the separate citations array — these would have shipped as literal bracket-debris in a "use verbatim" cold-email line. Fixed with `_strip_citations()` applied at extraction. Confirmed via a live re-run: brackets gone, corroboration still working correctly alongside it.
- **Sonnet 5 API drift, two distinct 400/crash bugs, neither guessable from training data — both required checking the claude-api skill / reading the actual error:** (a) Sonnet 5 (the whole 4.6+/5 family) rejects any NON-DEFAULT `temperature`/`top_p`/`top_k` outright — the fix is to OMIT the parameter entirely for Sonnet calls (`temperature=None` in `call_haiku_with_retry`), not adjust its value; Haiku call sites are unaffected and keep passing an explicit temperature. (b) Sonnet 5 runs adaptive thinking BY DEFAULT when `thinking` is omitted (a silent behavior change vs. Sonnet 4.6) — so `response.content[0]` is sometimes a `ThinkingBlock`, not the text block, and blind `content[0].text` indexing crashed the QA pass. Fixed by picking the first `type == "text"` block instead of assuming position 0; also gave `max_tokens` extra headroom (400 instead of 60/100) since it's now a shared ceiling across thinking + response text.
- **Cross-email duplication via the QA pass**: the QA critique step had zero awareness of what emails 1/2/3 in the same sequence already said, so on rewrite it could (and did, live) collapse email 3 into repeating email 1's exact fact/sentence almost verbatim — directly defeating the multi-angle feature's whole purpose. Fixed by threading `prior_lines` (the actual already-generated sibling email text, accumulated as `process_row` walks the 3 slots) into BOTH `build_user_prompt` (generation) and `build_qa_prompt` (QA), with an explicit "do not reuse the underlying fact/observation behind these" instruction in each, plus a `NO REPETITION` check added to the QA rubric. Verified live: re-ran, all 3 emails per lead now carry genuinely distinct facts.
- **Known minor residual**: `quiet_no_ads` and `high_reviews` can both legitimately fire on the same lead (both key off `review_count`, and the config allows them to co-occur when `ads_status=none`), so if BOTH end up selected across the 3 email slots they'll share the same underlying number even with genuinely different framing/implication. This is a config-level angle-overlap nuance, not a code bug — flagged here rather than engineered around, since the two lines observed live were differently-framed enough (ads-gap vs. membership-upsell) to still read as distinct, not a literal repeat.

Net effect on cost: full pipeline with everything on (Apify, corroboration, Sonnet generation, QA pass, multi-angle) is still cheap — corroboration roughly doubles Perplexity spend (raised `perplexity_daily_cap` to 1600 to avoid starving mid-batch), Sonnet is ~3x Haiku's per-token cost but output is capped tiny, multi-angle adds ~2 more generation+QA calls only for leads with enough distinct signal. Rough order of magnitude: a few dollars per 100 leads, still trivial at the real ~300/week volume Lorenzo runs.
