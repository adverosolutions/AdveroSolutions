Adapted from a downloaded n8n workflow JSON ("Deep Multiline Icebreaker System" course template) into `Agentic Worklfows/execution/deep_multiline_icebreaker.py` + `directives/USER/generate_deep_multiline_icebreaker.md`. Distinct from both `icebreaker_generator.py` (single-line Haiku opener) and the med-spa `relevance_line` tool in [[personalization-line-generator]] — this one researches multiple pages per lead. **As of 2026-07-25 (see correction #9, the current architecture) this is a TEMPLATE/ANGLE-LIBRARY system, not freeform LLM generation** — output is `"Hey {first_name}, {clause}"` where the clause is deterministically filled from Lorenzo's 15 reference templates VERBATIM (`ANGLES`, one wording per angle, no invented variants) based on which real signal was found, matching [[personalization-line-generator]]'s proven "auto-select highest-priority matching angle" pattern. Corrections #1-#7 document the freeform-generation era (superseded); correction #8 briefly added self-invented wording variants, which correction #9 reverted per Lorenzo's explicit instruction.

**Pipeline:** scrape lead's homepage → extract internal links → research up to 3 sub-pages (About/Services-style paths prioritized) → summarize each with Haiku → Sonnet 5 writes a personalized opener (JSON: `{opener}`) → write to CSV/Sheet.

**Scope correction #5 (2026-07-25, same session, immediately after #4): fixed forced-sounding repetition.** Correction #4's live test (4 leads) happened to produce "love that ..." on 3 of 4 outputs. Lorenzo: "debra's personalization is actually really good but the rest seem forced you dont have to say something you love about every single prospect." Root cause: only ONE few-shot example was seeded (the light-appreciation "Golden Goddess Facial" style), so the model anchored on that as its default template rather than genuinely varying. Fixed by:
- Replacing the single `FEW_SHOT_EXAMPLE_INPUT`/`OUTPUT` pair with a `FEW_SHOT_EXAMPLES` list of THREE deliberately different reaction styles (plain observation / mild surprise-curiosity / light appreciation), fed as alternating conversation turns so the model sees genuine variety, not one template to imitate.
- System prompt now explicitly instructs: "'love that .../love the ...' should be the occasional exception, not your default move... do not reach for affection just because it feels safe."
- Added a **batch-level mechanical guard** (same pattern as [[personalization-line-generator]]'s "ending-balance tracking"): `process_leads()` tracks `affection_count` via `AFFECTION_MARKERS = ("love that", "love the", "such a good")`; once affection-styled outputs exceed 40% of successes so far (with ≥3 samples), `generate_personalization(..., avoid_affection=True)` appends an explicit "avoid love that/the this time" note to that lead's prompt. Prompt instructions alone weren't trusted to hold at scale, matching the lesson already learned in the sibling tool.
- Live-verified on a bigger, more realistic 10-lead batch (7 succeeded, 3 skipped: one bot-walled 403, one SSL/TLS failure on `bougieaesthetics.net`, one no-content). Result: **zero "love that" occurrences across all 7** — genuine variety instead: "the Gold vs Black membership split for Botox units is a smart way to structure it" (plain) / "gold-infused facial is a new one for me" (mild surprise) / "didn't realize hidden door does hair and med spa both under one roof" (surprise) / "cryofacials next to hormone replacement therapy is a wild service mix" (curiosity). This is a stronger, more representative test than the earlier 4-lead runs — worth using a batch of ~10 rather than 4-5 for future spot-checks of this tool, since style-repetition problems don't reliably show up in tiny samples.

**Scope correction #6 (2026-07-25, same session, immediately after #5): correction #5 over-corrected — warmth needs to be REQUIRED, not just varied away from.** Lorenzo, after seeing #5's zero-"love that" output (things like "cryofacials next to hormone replacement therapy is a wild service mix"): "it should maintain being some sort of soft compliment though just so they keep guard down long enough to get to offer." This reframed the actual goal: warmth isn't optional flavor, it's a deliberate psychological device (disarm before the pitch lands elsewhere in the sequence) — the problem in correction #4 was never "too much warmth," it was "too little VARIETY in HOW the warmth is worded." Rebuilt again:
- All 3 `FEW_SHOT_EXAMPLES` now carry genuine warmth but with 3 different constructions ("respect that you still do...", "pretty cool you still do...", "the ... name is such a good one") — teaching wording-variety while keeping the warm function constant, instead of teaching "sometimes be warm, sometimes be neutral."
- System prompt rewritten: clause "needs to function as a LIGHT, GENUINE COMPLIMENT... this is NOT neutral trivia," explicitly lists alternative warm constructions to rotate through (respect that/pretty cool/nice touch/not many places/really like how/makes sense why), and explicitly bans backhanded-reading words ("wild", "interesting", "unusual" -- these read as judgment, not warmth, even though they're not literally negative).
- Replaced the `AFFECTION_MARKERS`/ratio-based guard with a **recency-based opener tracker**: `process_leads()` now keeps `recent_openers` (last 3 clauses' first-3-words, lowercased) and passes them to `generate_personalization(recent_openers=...)`, which tells the model "recent clauses opened with X, Y, Z -- use a different warm phrasing than those" -- steers away from REPEATING THE SAME WORDING, not away from warmth itself.
- Live re-verified on the same 10-lead batch (6 succeeded this run -- one dropped to `skipped_generation_failed` on a word-count-18 rejection, within normal noise): *"Hey Amir, nice that the Black Membership just builds in 20 units of Botox from day one"* / *"Hey Debra, the gold-infused Golden Goddess facial is such a fun signature touch"* / *"Hey Missy, 20+ years doing this and still leading every injection yourself, that's rare"* / *"Hey Melissa, respect that you offer the full JUVÉderm lineup, not just the one-size option"* / *"Hey Amy, nice touch offering non-surgical answers for jowls, not just surgery"* / *"Hey Carrie, not many spas have 30 years of nursing experience behind the treatments."* Every line now reads as a genuine, varied compliment — the actual target state.

**Scope correction #7 (2026-07-25, same session, immediately after #6): banned "+"-shorthand numbers.** Lorenzo, pointing at the two lines he liked best (Debra's — no number at all — and Carrie's "30 years of nursing experience" — a plain spoken number): "i think im liking the oness that do not drop a number better because no human would say 20+ years ever in conversation." The actual target wasn't "avoid numbers," it was "avoid the written '20+' shorthand specifically" — a plain round number said the way someone would say it out loud ("30 years") reads fine; the "+" symbol is what breaks the illusion of a real person talking. Fixed with: (a) a mechanical reject in `validate_clause()` — regex `\d\+` (any digit immediately followed by a `+`); (b) a prompt rule: cite numbers the way a person would say them out loud, or drop the exact count and describe qualitatively if it only sounds natural written with a "+". Live-verified on the same 10-lead batch (6/10 succeeded this run — 2 dropped to transient DNS/timeout scrape failures unrelated to this fix, within normal noise): zero "+" occurrences, e.g. "not many injectors can say they've been at this for 20 years" instead of "20+ years."

**Scope correction #8 (2026-07-25, same session, immediately after #7): full architecture rebuild — freeform LLM generation replaced with a deterministic angle/template library.** Lorenzo supplied 15 concrete reference templates with named variables (e.g. `{PrimaryTreatment: neurotoxin}` → "noticed you guys lean pretty heavy into neurotoxin work — solid reviews on the Botox side specifically", `{YearFounded}`, `{OwnershipType}`, `{LocationCount}`, `{GoogleReviewCount}`, a generic `{no variable}` fallback explicitly framed as "works generically for ~80% of prospects"). This wasn't more prompt-tuning — it's the same architecture pattern already proven in [[personalization-line-generator]] ("Angle library... Auto-selection: picks highest-priority angle whose triggers match"), now applied to this tool.

Rebuilt (`deep_multiline_icebreaker.py`):
- **`extract_signals()`**: ONE Haiku call per lead does STRUCTURED extraction only (never creative writing) against `SIGNAL_SCHEMA` — 11 fields (primary_treatment, specific_tech_brand, has_weight_loss_program, year_founded, ownership_type, location_count, neighborhood, has_membership_program, has_active_promo, is_founder_named, google_review_count), each null/false unless CLEARLY and EXPLICITLY stated in the research — same anti-fabrication discipline as before, just applied to structured fields instead of prose.
- **`ANGLES`**: ordered list of 14 angles (13 signal-gated + `fallback`, which requires nothing and always matches). First matching angle wins, exactly like the sibling tool's auto-selection.
- **Two of Lorenzo's original 15 NOT implemented, flagged rather than faked**: `GoogleReviewCount` — this tool only scrapes the spa's own site, which rarely shows an exact Google review count; supported only via an optional CSV passthrough column (`google_review_count`) for CRM-sourced leads that already have it (the `Med Spa Research Doc` sheet's `reviewCount` column is exactly this). `SocialPlatform`/`ContentType` (#12) — dropped entirely, this tool never visits social platforms at all, would need a real scraper that doesn't exist here.
- **Trimmed a few unverifiable/out-of-scope clauses from the given templates** rather than reproducing them verbatim: dropped "solid reviews on the Botox side"/"reviews are pretty stacked" (no review-sentiment signal exists to back that claim) from templates 1 and 3; dropped "which is basically what I do" from template 11 (pitch language, out of scope per correction #1). Flagged this trimming to Lorenzo transparently before building rather than silently rewriting his copy.
- **Sonnet 5 fully removed from this tool** — no creative-generation call exists anymore, only Haiku (summarization + extraction). Meaningfully cheaper and removes the whole class of freeform-generation problems (repetition, over-editorializing, banned-phrase whack-a-mole) that took 7 correction rounds to fight in the old architecture.
- **`shorten_company_name()`**: new deterministic helper (regex-strip common suffixes: "Med Spa", "Medical Spa", "Aesthetics", etc.) for the `{spa_name}` template variable — replaces what an LLM used to do ad-hoc.
- **Duplicate-text bug caught immediately on first live test and fixed same-turn**: with single-template angles (the three `primary_treatment_*` angles have no fill variable at all), 3 of 7 leads in a test batch got byte-identical output ("noticed you guys lean pretty heavy into neurotoxin work" verbatim for all 3) — a worse version of the exact repetition problem correction #5 fixed in the old architecture. Asked Lorenzo how to handle it; he chose "add 2-3 wording variants per angle, rotate" over "leave single template" or "fall through to next angle on repeat." Fixed: every angle in `ANGLES` now has a `templates` list (2-3 variants) instead of one `template` string; `select_and_fill_angle()` + `angle_usage` dict (threaded through `process_leads()`/`generate_personalization()`) round-robins through variants per angle across a batch — deterministic rotation, not random. Re-verified live: the same 3-lead neurotoxin collision now produces 3 distinct sentences.
- Output CSV/Sheet gained an `angle` column (which template fired) — same convention as `personalization_type` in [[personalization-line-generator]], useful for angle-distribution QA and future A/B analysis.
- Reliability side-effect: because `fallback` requires nothing, `skipped_generation_failed` should now stay near-zero — a lead only fails if the SITE fails to scrape, not because generated text failed validation. This is a real improvement over the freeform era, where validation rejections were common and silently dropped leads from a batch.

**Scope correction #10 (2026-07-26, same session, next turn after #9): real review-rating verification added, not another wording change.** After showing the literal-template output, Lorenzo stated a hard rule: "as long as the actual sentence is factual to the company then its fine if it doesnt apply its bad." Built:
- New `SIGNAL_SCHEMA` field `review_rating` (float, 1.0-5.0) — only filled if an explicit star rating/score is displayed on the site (never estimated from vague language like "great reviews").
- New derived field `reviews_confirmed_good` (bool, computed in `extract_signals()` after parsing, listed in `DERIVED_SIGNALS` so it's never asked of the extraction model directly) = `review_rating >= REVIEWS_CONFIRMED_MIN_RATING` (4.5). Deliberately NOT based on `google_review_count` alone — a review COUNT says nothing about sentiment (500 reviews could be 2-star), only an actual displayed rating counts.
- `primary_treatment_neurotoxin` and `primary_treatment_laser` angles in `ANGLES` now require `reviews_confirmed_good` in addition to their treatment-type signal. If not confirmed, these angles simply don't match and selection falls through to the next angle in priority order — **the template wording itself was never touched**, only the firing condition was tightened. This is meaningfully different from every prior correction in this file: it's not a copy/tone change, it's making the underlying signal more precise so a factual claim is only made when it's actually checkable.
- `_signal_present()` gained a `"float"` type branch (previously only bool/int/str) to support the new field.
- `review_rating` added to the existing CSV-passthrough mechanism alongside `google_review_count`/`year_founded`/`location_count`, since (same limitation as review count) star-rating widgets are typically JS-rendered and won't usually appear in raw scraped HTML text — without passthrough support this signal would rarely fire from live scraping alone.
