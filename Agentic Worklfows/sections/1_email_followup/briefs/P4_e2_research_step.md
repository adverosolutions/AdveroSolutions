## Build
0. **Spoken company name** (parked from the P2a review, rule 8): `spoken_company(name)` in `cadence.py` drops a trailing LLC / L.L.C. / Inc. / Inc / Corp / Co. / Ltd (with or without a comma) and a tagline after " - ", " | " or ":"; use it for `{company}` in E2, E4, E5 and for the research context's `company_spoken`. Never blank: if the result is empty, keep today's "hold for missing lead data" path.
1. `services/reply_engine/research.py`:
   - `fetch_pages(website, transport=None, resolver=None) -> List[Page]`: read-only GETs of the lead's own site: the home page plus at most 2 same-site pages whose link text or path says about / services / areas / locations / contact. http(s) only; the host must resolve to public addresses only (no private, loopback, link-local, reserved; the resolver is injected for tests); redirects only within the same registrable domain; short timeout; byte cap per page; honest User-Agent; no cookies kept. HTML to text with the stdlib (`html.parser`), scripts/styles dropped, whitespace collapsed. Any failure returns what was fetched so far (possibly nothing).
   - Identity is confirmed **by code, not the model**: the lead's phone digits (last 10) found on a fetched page -> `matched_on "phone"`; else the lead's city/metro found as a whole word -> `"city"`; else unconfirmed -> NONE.
   - `write_line(context, pages)`: one `shared.llm.complete("research", ...)` call with the rewritten prompt; the model returns strict JSON `{"line": str or "NONE", "facts": [{"text", "source_url", "excerpt"}]}`. Anything malformed is NONE.
   - Excerpt check by code: every fact's `excerpt` must appear verbatim (whitespace-normalised) in the fetched text of its `source_url`, and every `source_url` must be one of the fetched pages. Otherwise NONE. (The P1 validator trusts excerpts; this is what makes them real.)
   - `research_e2(state, now, store, dry_run=False, ...) -> dict` with `line`, `evidence`, `verdict` (from `research_rules.validate`), `source` ("researched" or "fallback"), `reasons`. Cache per lead in the engine store (own key, e.g. `research:<email>`) with `rules_sha`, so a held or retried E2 never pays twice; a cached line is re-validated (pure, cheap) before use, and a cache from another `rules_sha` is ignored. Dry run: may fetch and call (only when mode is "llm"), writes no store key.
2. `prompts/cadence_research.md`: rewrite to the agreed rules (sequence_final.md "Research line"), the six examples marked style-only, JSON output, NONE when unsure. The voice rules go in the prompt itself (no Claudeisms, no dashes, no "!", normal capitalization).
